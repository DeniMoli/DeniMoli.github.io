### Назначение деструктуризации

Когда вы работаете со структурой данных, такой как массив или литерал объекта, вы часто оказываетесь в ситуации, когда вам нужно получить некоторые или все значения, содержащиеся в структуре, и использовать их для инициализации дискретных переменных. Это упрощает работу с этими значениями, но, *исторически*, это может привести к довольно многословному коду:

```
const theArray = [ false, true, false ];
const firstElement = theArray[0];
const secondElement = theArray[1];
const thirdElement = theArray[2];
```

Это нормально! Я имею в виду, это *работает*; это происходит уже тридцать лет. Но в ES6 2015 года у нас появился гораздо более элегантный вариант: **деструктуризация**.

Деструктуризация позволяет извлекать отдельные значения из массива или объекта и присваивать их набору идентификаторов без необходимости доступа к ключам и/или значениям по одному. В своей самой простой форме, называемой **деструктуризацией шаблона привязки**, каждое значение распаковывается из массива или литерала объекта и присваивается соответствующему идентификатору, все из которых объявляются с помощью одного `let` или `const` (или `var`, технически, да, хорошо). Приготовьтесь, потому что это странно:

```
const theArray = [ false, true, false ];
const [ firstElement, secondElement, thirdElement ] = theArray;

console.log( firstElement );
// Result: false

console.log( secondElement );
// Result: true

console.log( thirdElement );
// Result: false
```

*Это* хорошая вещь, даже если немного странно видеть скобки по ту сторону оператора присваивания. Эта привязка охватывает ту же территорию, что и гораздо более подробный фрагмент над ней.

При работе с массивом отдельные идентификаторы заключаются в пару скобок в стиле массива, и каждый идентификатор, разделенный запятыми, который вы указываете в этих скобках, будет инициализирован значением в соответствующем элементе исходного массива. Иногда вы встретите деструктуризацию, называемую **распаковкой** структуры данных, но несмотря на то, что это звучит как «деструктуризация», исходный массив или объект не изменяются в процессе.

Элементы можно пропустить, опуская идентификатор между запятыми, точно так же, как вы пропускаете значение при создании разреженного массива:

```
const theArray = [ true, false, true ];
const [ firstElement, , thirdElement ] = theArray;

console.log( firstElement );
// Result: true

console.log( thirdElement );
// Result: true
```

Существует несколько различий в том, как деструктурировать объект с помощью деструктуризации шаблона привязки. Идентификаторы заключаются в пару фигурных скобок, а не в скобки; достаточно разумно, учитывая, что мы имеем дело с объектами. В самой простой версии этого синтаксиса используемые вами идентификаторы должны соответствовать ключам свойств:

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
const { theProperty, theOtherProperty } = theObject;

console.log( theProperty );
// result: true

console.log( theOtherProperty );
// result: false
```

Массив — это индексированная коллекция, а индексированные коллекции предназначены для использования там, где важен конкретный порядок итерации — например, с деструктуризацией здесь, где мы можем предположить, что указываемые нами идентификаторы будут соответствовать элементам массива в последовательном порядке.

Это не относится к объекту, который представляет собой набор ключей — в строго технических терминах это просто большая куча свойств, которые предназначены для определения и доступа к ним в *любом* порядке на основе их ключей. Однако на практике ничего страшного; Скорее всего, вы все равно захотите использовать имена идентификаторов ключей свойств (или что-то *очень* подобное) в качестве своих идентификаторов. Просто и эффективно, но недостатком является то, что он предполагает заданную… ну, *структуру* деструктурируемого объекта.

Это подводит нас к альтернативному синтаксису, который выглядит *абсолютно диким*, по крайней мере, для меня. Синтаксис имеет форму объектного литерала *, но очень, очень отличается — поэтому, прежде чем вы посмотрите на это, ненадолго забудьте все, что вы знаете об объектных литералах:

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
const { theProperty : theIdentifier, theOtherProperty : theOtherIdentifier } = theObject;

console.log( theIdentifier );
// result: true

console.log( theOtherIdentifier );
// result: false
```

Вы все еще не думаете об объектной буквальной записи, верно? Потому что если бы это было так, *вау* этот синтаксис выглядел бы странно. Я имею в виду ссылку на свойство, которое нужно деструктурировать, где будет ключ, и идентификаторы, где будут значения?

К счастью, мы сейчас даже немного не думаем об объектной нотации, поэтому мне вообще не нужно писать предыдущий абзац. Вместо этого мы можем сформулировать это следующим образом: в фигурных скобках, заключенных в круглые скобки, ноль или более разделенных запятыми экземпляров ключа свойства со значением, которое мы хотим, за которым следует двоеточие, за которым следует идентификатор, которому мы хотим присвоить значение этого свойства. После фигурных скобок оператор присваивания (`=`) и объект, подлежащий деструктуризации. Я знаю, что всего этого много в печати, но вы почувствуете это, воспользовавшись им несколько раз.

Второй подход к деструктуризации — это **деструктуризация по шаблону присвоения**. С помощью шаблонов присвоения значение каждого деструктурированного свойства присваивается конкретной цели — например, переменной, которую мы объявили с помощью `let` (или *технически*, `var`), свойству другого объекта или элементу массива.

При работе с массивами и переменными, объявленными с помощью `let`, деструктуризация шаблона присваивания на самом деле просто добавляет шаг, на котором вы объявляете переменные, которые в конечном итоге будут содержать деструктурированные значения:

```
const theArray = [ true, false ];
let theFirstIdentifier;
let theSecondIdentifier

[ theFirstIdentifier, theSecondIdentifier ] = theArray;

console.log( theFirstIdentifier );
// true

console.log( theSecondIdentifier );
// false
```

Это дает тот же конечный результат, что и при использовании деструктуризации шаблона привязки, например:

```
const theArray = [ true, false ];

let [ theFirstIdentifier, theSecondIdentifier ] = theArray;

console.log( theFirstIdentifier );
// true

console.log( theSecondIdentifier );
// false
```

Однако деструктуризация шаблона привязки позволит вам использовать `const` сразу:

```
const theArray = [ true, false ];

const [ theFirstIdentifier, theSecondIdentifier ] = theArray;

console.log( theFirstIdentifier );
// true

console.log( theSecondIdentifier );
// false
```

Теперь, если вы захотите использовать эти деструктурированные значения для заполнения другого массива или свойств объекта, вы столкнетесь с предсказуемой стеной двойного объявления при использовании деструктуризации шаблона привязки:

```
// Error
const theArray = [ true, false ];
let theResultArray = [];

let [ theResultArray[1], theResultArray[0] ] = theArray;
// Uncaught SyntaxError: redeclaration of let theResultArray
```

Мы не можем заставить `let`/`const`/`var` делать что-либо, кроме создания переменных; это все их дело. В примере выше первая часть строки интерпретируется как `let theResultArray`, и мы получаем ошибку: `theResultArray` уже объявлен.

Такой проблемы нет, когда мы используем деструктуризацию шаблона присваивания:

```
const theArray = [ true, false ];
let theResultArray = [];

[ theResultArray[1], theResultArray[0] ] = theArray;

console.log( theResultArray );
// result: Array [ false, true ]
```

Еще раз: этот синтаксис применим и к объектам, но с некоторыми небольшими нюансами:

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
let theProperty;
let theOtherProperty;

({ theProperty, theOtherProperty } = theObject );

console.log( theProperty );
// true

console.log( theOtherProperty );
// false
```

Вы заметите пару скобок, устраняющих неоднозначность, вокруг строки, где мы выполняем деструктуризацию. Вы видели это раньше: без оператора группировки пара фигурных скобок в контексте, где ожидается оператор, считается блочным оператором, и вы получаете синтаксическую ошибку:

```
// Error
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
let theProperty;
let theOtherProperty;

{ theProperty, theOtherProperty } = theObject;
// Uncaught SyntaxError: expected expression, got '='
```

Пока что это не делает ничего такого, чего не могла бы сделать деструктуризация шаблона привязки. Мы используем идентификаторы, соответствующие ключам свойств, но подойдет любой идентификатор, если мы используем альтернативный синтаксис деструктуризации объекта:

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
let theFirstIdentifier;
let theSecondIdentifier;

({ theProperty: theFirstIdentifier, theOtherProperty: theSecondIdentifier } = theObject );

console.log( theFirstIdentifier );
// true

console.log( theSecondIdentifier );
// false
```

Еще раз: деструктуризация связывающего шаблона не может сделать ничего. Но *в отличие* от деструктуризации шаблона привязки, любой тип цели назначения будет работать с деструктуризацией шаблона назначения:

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : false
};
let resultObject = {};

({ theProperty : resultObject.resultProp, theOtherProperty : resultObject.otherResultProp } = theObject );

console.log( resultObject );
// result: Object { resultProp: true, otherResultProp: false }
```

Используя любой синтаксис, вы можете установить значения «по умолчанию», которые будут использоваться, если элемент или свойство вообще отсутствует или содержит явное значение `undefined`:

```
const theArray = [ true, undefined ];
const [ firstElement, secondElement = "A string.", thirdElement = 100 ] = theArray;

console.log( firstElement );
// Result: true

console.log( secondElement );
// Result: A string.

console.log( thirdElement );
// Result: 100
```

```
const theObject = {
  "theProperty" : true,
  "theOtherProperty" : undefined
};
const { theProperty, theOtherProperty = "A string.", aThirdProperty = 100 } = theObject;

console.log( theProperty );
// Result: true

console.log( theOtherProperty );
// Result: A string.

console.log( aThirdProperty );
// Result: 100
```

Конечно, это шикарная штука, но этот синтаксис действительно хорош, когда вы распаковываете *вложенные* массивы и объекты. Естественно, ничто не мешает вам распаковать объект, который содержит объект в качестве значения свойства, а затем распаковать этот внутренний объект отдельно:

```
const theObject = {
  "theProperty" : true,
  "theNestedObject" : {
    "anotherProperty" : true,
    "stillOneMoreProp" : "A string."
  }
};

const { theProperty, theNestedObject } = theObject;
const { anotherProperty, stillOneMoreProp = "Default string." } = theNestedObject;

console.log( stillOneMoreProp );
// Result: A string.
```

Но мы можем сделать этот путь более кратким. Нам не обязательно распаковывать вложенный объект отдельно — мы можем распаковать его как часть той же привязки:

```
const theObject = {
  "theProperty" : true,
  "theNestedObject" : {
    "anotherProperty" : true,
    "stillOneMoreProp" : "A string."
  }
};
const { theProperty, theNestedObject : { anotherProperty, stillOneMoreProp } } = theObject;

console.log( stillOneMoreProp );
// Result: A string.
```

От объекта внутри объекта к трем простым в использовании константам в одной строке кода.

Столь же лаконично мы можем распаковать смешанные структуры данных:

```
const theObject = [{
  "aProperty" : true,
},{
  "anotherProperty" : "A string."
}];
const [{ aProperty }, { anotherProperty }] = theObject;

console.log( anotherProperty );
// Result: A string.
```

*Плотный* синтаксис, в этом нет сомнений — даже граничащий с «непрозрачным». Возможно, потребуется немного поэкспериментировать, чтобы освоить этот метод, но как только он сработает, деструктуризация присваивания предоставит вам невероятно быстрый и удобный способ разбить сложные структуры данных, не создавая кучу промежуточных структур данных и значений.

### Остальные свойства

Во всех приведенных выше примерах мы работали с известными величинами: «превратим эти свойства или элементы X в переменные Y». Это не соответствует реальности разрушения огромного запутанного объекта, битком набитого массива или того и другого.

В контексте деструктурирующего присваивания многоточие (это `...`, а не `…`, для моих коллег-энтузиастов Unicode), за которым следует идентификатор (в духе `...theIdentifier`), представляет собой **rest-свойство** — идентификатор, который будет представлять *остальную* часть распаковываемого массива или объекта. Это оставшееся свойство будет содержать все оставшиеся элементы или свойства, помимо тех, которые мы явно распаковали в их собственные идентификаторы, и все они объединены в ту же структуру данных, что и та, которую мы распаковываем:

```
const theArray = [ false, true, false, true, true, false ];
const [ firstElement, secondElement, ...remainingElements ] = theArray;

console.log( remainingElements );
// Result: Array(4) [ false, true, true, false ]
```

Обычно я намеренно стараюсь избегать использования примеров, которые слишком близки к реальному использованию, поскольку они могут показаться немного запутанными, и я не хочу отвлекать от основных идей, но в данном случае «запутанность» — это именно то, что мы хотим обойти. Итак, давайте воспользуемся объектом, который мне близок и дорог: (частью) данных, представляющих самый первый информационный бюллетень, который я разослал, когда начал писать этот курс.

```
const firstPost = {

Там довольно много всего происходит. Для целей этого упражнения предположим, что данные поступают из внешнего API, как это происходит на моем веб-сайте — это не объект, который мы контролируем. Конечно, мы можем работать с этим объектом напрямую, но это немного громоздко, когда все, что нам нужно, это, например, заголовок и тело информационного бюллетеня:

```
const firstPost = {
  "id": "mat-update-1.md",

    "title": "Meet your Instructor",
    "pubDate": "2025-05-08T09:55:00.630Z",
    "headingSize": "large",

  }

Это *аккуратно*; пара десятков персонажей и у нас есть именно то, что нам нужно из этого клубка. Я знаю, что мне не понадобятся эти свойства `id` или `slug` для публикации на моем собственном веб-сайте, поэтому я их вообще опускаю, но этот внутренний объект `data` имеет заметное звучание, как будто можно было бы ожидать, что он будет содержать другие свойства, связанные с будущими публикациями. Я не знаю, какими будут эти свойства, но знаю, что хочу, чтобы все они были упакованы таким образом, чтобы я мог легко ими пользоваться. Мне нужно свойство `firstPost.data.title` изолированно, но мне также нужен объект, содержащий все *остальные* свойства `firstPost.data`, какими бы они ни были в конечном итоге:

```
const firstPost = {
  "id": "mat-update-1.md",
  "slug": "mat-update-1",
  "body": "Hey, great to meet you, everybody. I'm Mat — \\"Wilto\\" is good too — and I'm here to teach you JavaScript. Not just what JavaScript is or what JavaScript does, but the *how* and the *why* of JavaScript. The weird stuff. The *deep magic_.\\n\\nWell, okay, I'm not *currently* here to teach you JavaScript, but I will be soon. Right now I'm just getting things in order for the course — planning, outlining, polishing the fancy semicolons that I only take out when I'm having company over, writing like 5,000 words about `this` as a warm-up that completely got away from me, that kind of thing.",
  "data": {
    "title": "Meet your Instructor",
    "pubDate": "2025-05-08T09:55:00.630Z",
    "headingSize": "large",
    "showUnsubscribeLink": true,
    "stream": "javascript-for-everyone"
  }
};

const { data : { title, ...metaData }, body } = firstPost;

console.log( title );
// Result: Meet your Instructor

console.log( metaData );
// Result: Object { pubDate: "2025-05-08T09:55:00.630Z", headingSize: "large", showUnsubscribeLink: true, stream: "javascript-for-everyone" }
```

*Теперь* мы разговариваем. Теперь у нас есть объект `metaData`, содержащий все остальное в свойстве `data` объекта, который нам был передан.

Слушать. Если вы хоть немного похожи на меня, даже если вы еще не совсем разобрались в самом синтаксисе, вы обнаружите, что в привязке в приведенном выше фрагменте есть что-то интуитивно приятное. Вся эта работа выполняется в одной строке кода. Он краток и элегантен — он берет сложное и делает его простым. Это хорошая вещь.

И все же: может быть, ты тоже это слышишь, хоть и очень слабо? Тихий голос где-то в глубине вашего сознания спрашивает: «Интересно, есть ли еще лучший способ». Для того, что мы делаем здесь, изолированно, это решение почти настолько хорошо, насколько оно возможно, но что касается широкого мира JavaScript: *всегда* есть лучший способ. Если вы еще не слышите это, то держу пари, что услышите к концу курса.

Любой, кто пишет JavaScript, является разработчиком JavaScript; в этом нет двух способов. Но удовлетворение от создания порядка из хаоса всего за несколько нажатий клавиш и стремление найти еще лучшие способы сделать это? Это задатки разработчика JavaScript, с которыми следует * считаться*.
